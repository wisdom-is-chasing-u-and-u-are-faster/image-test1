# Architecture Decision Record (ADR-001): Serverless Event-Driven Platform Topology

## Status
APPROVED

## Context & Problem Statement
Legacy ticketing platforms suffer from monolithic scaling bottlenecks, brittle synchronous HTTP coupling, and slow incident triage during enterprise-wide outages. The system must support elastic auto-scaling from 0 to 50 instances in < 3s, guarantee sub-200ms P99 ingestion latency, achieve sub-500ms routing, and enforce strict audit non-repudiation.

## Decision
We adopt **Option B: Serverless Event-Driven Topology** leveraging Google Cloud services:
1. **Google Cloud Run**: Stateless microservices handling ingestion, status transitions, search, and callbacks with auto-scaling to zero.
2. **Google Cloud Pub/Sub**: Fully managed event broker with partition keys on `ticket_id` decoupling intake, routing, search indexing, and notifications.
3. **Google Cloud Tasks**: Delayed HTTP callback invocation executing at 50%, 75%, and 100% SLA intervals, completely eliminating polling cron jobs.
4. **Cloud SQL PostgreSQL 15+**: Primary relational datastore with Row-Level Security (RLS), optimistic concurrency locking (`expected_version`), and cryptographic SHA-256 triggers on `ticket_audit_ledger`.
5. **OpenSearch / Elasticsearch**: Managed search cluster providing sub-150ms faceted full-text querying.

## Consequences
- **Positive**: Low idle infrastructure costs, horizontal elastic scale, decoupled microservices, and tamper-evident audit trails.
- **Negative / Trade-offs**: Eventual consistency on search index (bounded to <= 1s lag); requires idempotency keys and outbox retry patterns for resilient event delivery.
